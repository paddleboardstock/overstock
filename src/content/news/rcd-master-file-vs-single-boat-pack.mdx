## Two Layers of RCD Documentation

RCD compliance requires two distinct but interconnected documentation systems. The **master technical file** proves that a boat design meets the Recreational Craft Directive. The **single-boat traceability pack** (also called a boat build pack) proves that each individual hull produced matches the approved design. Confusing these two layers is one of the most common documentation failures in RIB manufacturing.

## Master Technical File: Proving the Design

The master technical file is created once per model or model variant. It contains:

- **Design specifications and General Arrangement (GA) drawings** — defining hull form, tube geometry, and structural layout
- **Stability and buoyancy calculations** — per ISO 12217 and ISO 6185, showing compliance with the declared design category
- **Structural analysis** — scantling calculations, material specifications, and laminate schedules for GRP or alloy structures
- **Test reports** — type examination results from the notified body, including prototype test data
- **Risk assessment** — systematic evaluation of hazards and the design measures taken to mitigate them
- **Compliance matrix** — mapping each RCD Annex I Essential Requirement to the supporting evidence
- **Notified body documentation** — type examination certificate, quality system approval, and module assessment records

The master file is retained for **10 years** after the last unit of that model is placed on the market, as required by RCD Article 7.

## Single-Boat Build Pack: Proving the Hull

Each boat leaving the factory must have a traceability pack linking it to the master file. This pack contains:

- **HIN record** — the Hull Identification Number linking this specific hull to the model type
- **Production deviation log** — any material substitutions, design modifications, or process changes from the master file
- **Incoming material certificates** — fabric batch numbers, resin batch numbers, alloy heat numbers
- **In-process inspection records** — tube pressure test results, hull layup records, bond line inspections
- **Final inspection checklist** — builder plate data verification, CE marking placement, safety equipment fitment
- **Conformity verification** — signed confirmation that this specific unit matches the type-approved design

## HIN-Based Retrieval: The 24-48 Hour Window

When EU market surveillance authorities request documentation, they identify the boat by its HIN. The manufacturer must retrieve and supply the relevant documentation within a reasonable timeframe — typically 24 to 48 hours. This means:

- The HIN must be the primary index key in your documentation system
- The master file for the declared model must be immediately accessible
- The build pack for the specific HIN must be retrievable from production records
- Both sets must be cross-referenced and internally consistent

## Minimum Viable Documentation System

A practical RIB documentation system needs:

1. **Digital master file repository** — one folder per model, version-controlled
2. **Build pack template** — pre-populated with master file references, completed per hull at production
3. **HIN index database** — linking every HIN to its model, build date, and build pack location
4. **Access protocol** — named responsible person, retrieval procedure, and format for authority responses
5. **Retention schedule** — 10-year minimum, with destruction policy and audit trail
